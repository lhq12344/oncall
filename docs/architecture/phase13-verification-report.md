## Architecture Cutover Evidence

- Legacy directories `backend/internal/toolkit`, `backend/internal/slash`, `backend/internal/permissions`, `backend/internal/compact`, and `backend/internal/workflow/agentteams` are absent.
- Raw repository scans have no matches for legacy SSE sentinels, frontend Go map command parsing, controller-local `NewV1` constructors, or global Elasticsearch singleton names.
- Frontend stream handling consumes only `oncall.event/v1` RunEvent frames; `LegacyStreamEvent`, `legacyToRunEvent`, `reduceLegacyStreamEvent`, and legacy Stringer interrupt parsing have been removed.
- Prompt assembly uses `DefaultAssembler` and `fromSection`; compatibility-era `CompatibilityAssembler` and `fromLegacySection` names are absent.
- Permission checking now lives under `backend/internal/tools/policy/permissions`; `backend/internal/tools/policy/legacy` is absent and forbidden by architecture tests.
- Hybrid RAG uses V2 vector retrieval plus BM25 fallback; old embedding collection fallback names such as `LegacyRetriever`, `embedding_legacy`, `legacy_knowledge`, and `legacy_ops_cases` are absent from RAG and dialogue paths.
- Incident remediation proposal parsing accepts the current `actions` contract only; old commands-only plan payloads no longer mutate incident proposal state.
- Incident execution state bridging no longer accepts the old `execution` stage alias; execution updates now flow through `execute_plan` and verification updates through `verify_plan`.
- The compact package keeps the real runtime middleware and no longer includes the old migration-status placeholder file.
- The skills package keeps catalog, loader, activation, metadata, and security modules; the unused middleware compatibility probe has been removed.
- Chat, chat resume, AI ops, AI ops resume, and slash-triggered streams emit `oncall.event/v1` RunEvent frames instead of direct legacy SSE payloads.
- Changed and untracked text files are clean of trailing whitespace and merge conflict markers.
- `backend/internal/arch/architecture_test.go` enforces the final cutover checks, including the rule that only `backend/internal/tools/registry.go` may declare the canonical Tool Registry.
- `backend/internal/tools/runtime` is a deferred gateway catalog, not a second Tool Registry.
- `frontend/src/agent-events/reducer.test.ts` verifies duplicate replayed tool-result events are not displayed twice after reconnect.
- `backend/internal/improvement/capture_test.go` verifies all six ReviewCase entry points required by the data flywheel are capturable.
- `backend/internal/config/config_test.go` and `backend/internal/app/application_test.go` verify Redis, Elasticsearch, Milvus, and Trace are optional by default and become required only through explicit configuration.
- `backend/internal/tools/policy/engine_test.go` verifies mutation approvals are bound to tool version, arguments, target resource, cluster, namespace, plan id, plan revision, and snapshot hash.
- `backend/internal/improvement/flywheel_test.go` verifies the data flywheel governance drill from traceable ReviewCase through triage, knowledge candidate creation, staging/eval/canary, publish, redaction, and rollback-version preservation.
- `backend/internal/telemetry/recorder_test.go` verifies Trace, Metric, and Audit attributes are redacted before records reach adapter sinks such as CozeLoop.
- `backend/internal/arch/architecture_test.go` parses the machine-readable checklist and fails if required external gates disappear or local gates are not marked complete.

## Environment-Limited Gates

The following gates are not proven by this local run because they require host
tooling or external services:

- `go test -race ./...` still cannot run directly on this Windows host until a C compiler is available on `%PATH%`; with `CGO_ENABLED=1`, Go reports `cgo: C compiler "gcc" not found`. The local verification script now covers this host by falling back to WSL when available.
- Live hybrid retrieval is not proven by the offline BM25 CLI; Milvus, embedding retrieval, query rewrite, fusion, rerank, and the running chat service need an integration environment.
- CozeLoop live trace inspection still requires operator evidence from the CozeLoop UI/API, but the official CozeLoop API endpoint is reachable and passes the live connectivity gate.
- Redis, Elasticsearch, Milvus, Kubernetes, and CozeLoop fault injection beyond unit-level degraded-path tests requires service endpoints or test doubles wired at the deployment/integration layer.
- SSE long-connection pressure testing requires a running backend/frontend environment and `ONCALL_LIVE_SSE_PRESSURE=1`; the live harness opens concurrent reconnecting stream clients against `ONCALL_LIVE_CHAT_STREAM` or the default `/api/v1/chat_stream` route, and fails on `error`/`run.failed` frames instead of accepting any versioned frame. A 2026-09-04 rerun completed this gate successfully.
- Live backend model validation is no longer blocked by the previous unavailable gateway model after switching the checked-in chat config to DeepSeek `deepseek-v4-flash`; keep `ONCALL_CHAT_BASE_URL`, `ONCALL_CHAT_MODEL`, and `ONCALL_CHAT_API_KEY` available as runtime overrides for future provider changes.
- Live mutation approval drill still needs a running backend/UI path to prove the transport preserves the same snapshot-binding semantics covered by unit tests.
- Live data flywheel drill still needs a running hybrid RAG stack to prove a canary-published item is retrievable after publish.
